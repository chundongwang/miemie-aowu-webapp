## Traffic path and China access

Most mainstream hosting/database services (Vercel, Supabase, PlanetScale, Neon, Firebase) are blocked or unreliable in mainland China, so the app runs on Cloudflare Workers + D1 + R2.

Cloudflare's in-China network (JD Cloud partnership) is an **Enterprise add-on that also requires an ICP filing**. On normal plans, mainland visitors reach Cloudflare edges outside China, and the client → Cloudflare-edge hop was slow and lossy for China Unicom users (ITDOG: ~28% failures, 5.49 s median).

Since 2026-10-10 the public hostnames are served through a Hong Kong VPS (DMIT, Eyeball routing):

```
client ──HTTPS──▶ miemieaowu.ai / www  (DNS-only A → 191.222.220.97, DMIT HK)
                   nginx: Let's Encrypt cert, caches /_next/static, /api/photos, /api/media
                   │  HTTPS, Host/SNI cf-origin.miemieaowu.ai (~1 ms to Cloudflare HKG)
                   ▼
                 Cloudflare Worker miemie-aowu-webapp ─▶ D1, R2
```

- The Worker code, D1 and R2 are unchanged; `cf-origin.miemieaowu.ai` is the Worker's only custom domain (`wrangler.toml`).
- The iOS app (Capacitor, `server.url = https://miemieaowu.ai`) followed the DNS change with no App Store update.
- nginx config: `deploy/dmit-shadow/`. Design, risks and rollback: `docs/ios-capacitor-zero-update-routing.md`.

## Database Schema

### `users`

```sql
CREATE TABLE users (
  id          TEXT PRIMARY KEY,           -- nanoid
  username    TEXT NOT NULL UNIQUE,
  email       TEXT NOT NULL UNIQUE,
  password_hash TEXT NOT NULL,
  display_name TEXT NOT NULL,
  created_at  INTEGER NOT NULL            -- unix timestamp
);
```

### `lists`

```sql
CREATE TABLE lists (
  id              TEXT PRIMARY KEY,
  owner_id        TEXT NOT NULL REFERENCES users(id),
  recipient_id    TEXT REFERENCES users(id),  -- null until shared
  title           TEXT NOT NULL,
  emoji           TEXT NOT NULL DEFAULT '📋',
  category        TEXT NOT NULL DEFAULT 'custom',  -- 'coffee', 'music', 'restaurant', 'book', 'movie', 'custom'
  secondary_label TEXT,                -- e.g. "Artist", "Address" — overrides category default
  created_at      INTEGER NOT NULL,
  updated_at      INTEGER NOT NULL
);
```

### `items`

```sql
CREATE TABLE items (
  id            TEXT PRIMARY KEY,
  list_id       TEXT NOT NULL REFERENCES lists(id) ON DELETE CASCADE,
  name          TEXT NOT NULL,
  secondary     TEXT,                  -- address, artist, author, etc.
  reason        TEXT,
  status        TEXT NOT NULL DEFAULT 'unseen',  -- 'unseen' | 'saved' | 'done'
  position      INTEGER NOT NULL DEFAULT 0,       -- for manual reordering
  created_at    INTEGER NOT NULL,
  updated_at    INTEGER NOT NULL
);
```

### `item_photos`

```sql
CREATE TABLE item_photos (
  id        TEXT PRIMARY KEY,
  item_id   TEXT NOT NULL REFERENCES items(id) ON DELETE CASCADE,
  r2_key    TEXT NOT NULL,            -- R2 object key
  position  INTEGER NOT NULL DEFAULT 0
);
```

### `invite_links`

```sql
CREATE TABLE invite_links (
  token       TEXT PRIMARY KEY,        -- random 24-char token
  list_id     TEXT NOT NULL REFERENCES lists(id) ON DELETE CASCADE,
  created_at  INTEGER NOT NULL,
  expires_at  INTEGER,                 -- null = no expiry
  used_by     TEXT REFERENCES users(id)
);
```

## API Routes

All routes are under `/api`. Auth is via a short-lived JWT in an `HttpOnly` cookie.

### Auth

| Method | Path | Description |
|---|---|---|
| POST | `/api/auth/register` | Create account |
| POST | `/api/auth/login` | Get JWT cookie |
| POST | `/api/auth/logout` | Clear cookie |
| GET | `/api/auth/me` | Current user |

### Lists

| Method | Path | Description |
|---|---|---|
| GET | `/api/lists` | Lists owned or shared with me |
| POST | `/api/lists` | Create a list |
| GET | `/api/lists/[id]` | Get list + items |
| PATCH | `/api/lists/[id]` | Update title/emoji/label |
| DELETE | `/api/lists/[id]` | Delete list (owner only) |
| POST | `/api/lists/[id]/share` | Share with user by username |
| DELETE | `/api/lists/[id]/share` | Revoke sharing |
| POST | `/api/lists/[id]/invite` | Generate invite link |

### Items

| Method | Path | Description |
|---|---|---|
| POST | `/api/lists/[id]/items` | Add item |
| PATCH | `/api/items/[id]` | Update item fields |
| PATCH | `/api/items/[id]/status` | Update status (unseen/saved/done) |
| DELETE | `/api/items/[id]` | Delete item |
| POST | `/api/items/[id]/photos` | Upload photo (returns R2 URL) |
| DELETE | `/api/items/[id]/photos/[photoId]` | Remove photo |

### Users

| Method | Path | Description |
|---|---|---|
| GET | `/api/users/search?q=` | Find user by username (for sharing) |

## Capacitor Integration

### Setup

```bash
npx cap init
npx cap add ios
npx cap add android
```

The `capacitor.config.ts` points to the Next.js dev server during development and to the built static output (or a remote URL) in production.

### Plugins used

| Plugin | Purpose |
|---|---|
| `@capacitor/camera` | Photo picker / camera |
| `@capacitor/push-notifications` | Push notifications |
| `@capacitor/haptics` | Swipe feedback |
| `@capacitor/status-bar` | Status bar styling |

### Build flow

```
next build → next export (static) → npx cap sync → Xcode / Android Studio
```

For features that require server-side rendering (API routes), the mobile app hits the deployed Cloudflare Pages URL. The Capacitor shell is a thin native wrapper around the web UI — it does not bundle a local server.

## Auth Flow

1. User submits email + password
2. Server checks `users` table, verifies bcrypt hash
3. Signs a JWT (`{ sub: userId, exp: +7d }`) with a secret stored in Cloudflare Workers env
4. Sets `Set-Cookie: token=...; HttpOnly; Secure; SameSite=Strict`
5. Client never sees the raw JWT — all subsequent API calls send the cookie automatically

Password reset v1: out of scope (manual support).

---

## Photo Upload Flow

1. Client calls `POST /api/items/[id]/photos` with the file (multipart)
2. API route streams the file to R2 under key `items/{itemId}/{photoId}`
3. Returns a signed R2 URL (or a proxy URL through the API) for display
4. `item_photos` row is created

Photos are served through a Cloudflare R2 public bucket or a Worker that adds auth checks.

## Open Questions

- **Push notifications in China**: APNs (iOS) and FCM (Android) are both blocked in mainland China. May need to integrate with a China-licensed push provider (e.g., JPush / 极光推送) for users on the mainland, and fall back to FCM/APNs for international users. This can be deferred to a later milestone.
- **ICP license**: If the app gains a custom domain served from within China, an ICP filing (ICP备案) may eventually be required. Cloudflare's China network operates under JD Cloud's license, which covers general use but worth monitoring.
- **Image moderation**: If photos are user-uploaded and the app operates in China, consider adding content moderation (Alibaba Cloud Green or similar) before going public.
